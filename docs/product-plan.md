# Cow Skate — продуктовый план: реиграбельность и соревнование

Документ для агента-исполнителя. Цель — чтобы хотелось сыграть «ещё
один заезд» и обогнать друзей в чате. Здесь — что делаем, зачем, точные
числа, где в коде, критерии готовности. Числа — стартовые, тюнятся
плейтестом (тюнинг — отдельные коммиты с пометкой `tune:`).

**Прогресс.** Фазы выполняются по порядку, одна фаза = одна сессия/
ветка коммитов. Завершив фазу, отметить её заголовок:
`**Выполнено** (коммиты …)`. Открытые вопросы §7 решает пользователь;
ответы фиксируются здесь же рядом с вопросом.

Связанные документы (читать перед работой):

- `AGENTS.md` — правила проекта, гейт коммита (lint, `tsc --checkJs`,
  `make standalone`, pytest, `npm run snapshot`).
- `docs/refactoring-map.md` §5 — рецепт новой конструкции трассы.
- `docs/gameplay-ux-plan.md` §C — виды трамплинов (стол, пропасть, рейл).
- `backend/app/static/game/types.d.ts` — все новые типы/события сюда.

Звук — **вне скоупа** этого плана (бэклог, см. конец).

## 0. Диагноз: почему надоедает

| #   | Проблема                                                                                                                                                                    | Где в коде                                                       |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| P1  | Сложность плоская: за ~14 с скорость выходит на `CRUISE` и больше не растёт, плотность спавна постоянна. Ритм заучивается за 2–3 заезда.                                    | `main.js:stepSpeed`, `spawnFeatures`, `gapAfterCowH` в `track/*` |
| P2  | Нет ставки внутри заезда: множитель живёт только в одном вылете (`mult = число трюков в воздухе`). Нечего «раскручивать» и жалко терять.                                    | `score.js:award`                                                 |

## 1. Ядро — принятые продуктовые решения

Помечены `PD1…`. Отмечены **(?)** — рекомендованный вариант, но перед
реализацией подтвердить у пользователя (см. «Открытые вопросы»).

- **PD1. Заезд = сущность модели.** Явные события `run-start` /
  `run-end`, статистика заезда, одна отправка счёта в конце.
- **PD2. 3 жизни на заезд (?).** Крэш отнимает жизнь и сжигает
  несданное комбо; заезд кончается на 0 жизней. Так у комбо появляется
  ставка, а казуал не теряет всё за одну ошибку.
- **PD3. Комбо-цепь с «банком».** Очки за действия копятся в горшке
  цепи × множитель. Цепь закрывается по таймауту — горшок сдаётся в
  счёт. Крэш — горшок сгорает. Это главный крючок (жадность против риска).
- **PD4. Разнообразие и тайминг дороже спама.** Повтор одного трюка в
  цепи дешевеет, идеальное приземление — бонус.
- **PD5. Трасса крепчает с дистанцией.** Зоны каждые 500 м: быстрее,
  плотнее, новые конструкции и паттерны.
- **PD6. Соперник на экране.** HUD показывает следующего в топе чата
  и сколько до него осталось. Обгон — событие с попапом.
- **PD7. Цели между заездами.** Коллектибл-клевер, 3 миссии, уровень
  фермера, косметика. Только визуал — на баланс не влияет.
- **PD8. Честное соревнование.** Недельный топ и «Трасса дня»
  (одинаковый сид для всех).

## 2. Фазы реализации (строго по порядку)

Каждая фаза — отдельная ветка коммитов. Поведенческие изменения меняют
хэши снапшота → эталон обновлять **отдельным коммитом** с описанием,
почему поменялось. Новые вызовы `Math.random` — только в поведенческих
коммитах. Новые случайности по возможности брать из отдельного
генератора (см. фазу 6), чтобы не сдвигать порядок существующих.

### Фаза 0. Жизненный цикл заезда (фундамент, P7)

**Модель** — новый модуль `game/run.js` (владелец `state.run`):

```ts
// types.d.ts
interface RunStats {
  tricks: number; // приземлённые трюки (без double)
  obstacles: number; // взятые препятствия
  loops: number; // пройденные петли
  coins: number; // фаза 3
  maxMult: number; // максимальный множитель цепи (фаза 1)
  crashes: number;
}
interface RunState {
  n: number; // номер заезда в сессии, с 1
  t0: number; // state.t старта
  distM: number; // пройдено метров
  lives: number; // фаза 1 (PD2); до неё — 1
  stats: RunStats;
}
// GameState: run: RunState | null  (null — демо/между заездами)
// GameEventMap:
//   'run-start': { n: number }
//   'run-end':   { score; distM; durationS; stats: RunStats; reason: 'crash' | 'idle' }
```

- **Старт.** Первый ввод из демо — то, что сейчас делает `touched()`
  при `!playerMode()`. `ui.js` вызывает `startRun()` из `run.js`, а не
  трогает `state.score`/`playT0` напрямую. `playT0` переставляется на
  каждом старте: мягкий разгон 14 с — на каждый заезд, а не только на
  первый.
- **Дистанция.** `distM += speed * dt * M_PER_COWH`,
  `M_PER_COWH = 1.5` (константа, `constants.js`). Только в `mode !== 'crash'`.
- **Конец.**
  - (а) Крэш: до фазы 1 — сразу, после — при `lives === 0`.
  - (б) Бездействие: автопилот перехватил управление (`playerMode()`
    стал false) → `run-end` с `reason: 'idle'`. Сейчас демо подхватывает
    заезд молча, счёт «висит» — это ломает соревнование.
- **Счёт.**
  - `addScore` больше не вызывает `endRun()`. Рекорд пишется и
    `cowskate:run-end` уходит **один раз** — в обработчике `run-end`.
  - В `detail` — `{score, best, distM, durationS, stats}`, где
    `score` — счёт **заезда**, а не рекорд.
  - `telegram-bridge.js:submitScore` шлёт счёт **каждого** заезда, а не
    только рекорд: это нужно недельному топу и статистике. Сервер сам
    решает, рекорд ли это (`is_new_best` уже есть).
- **HUD.** Добавить дистанцию `1 234 м` мелко под счётом
  (`index.html` + `ui.js:hud`, обновлять не чаще целого метра).
- **Карточка результата** (`ui.js:showResult`), расширить:
  - счёт заезда и пометка `НОВЫЙ РЕКОРД`, если побит;
  - дистанция, лучший множитель, число трюков;
  - место в топе — приходит асинхронно из ответа `/api/score`: мост
    шлёт DOM-событие `cowskate:rank` `{rank, prevRank}`, `ui.js`
    дописывает строку «#5 в общем топе (было #7)»;
  - держать на экране 3.5 с (сейчас 2.6).

**Бэкенд** (миграция `0002`):

- `ScoreRun` + nullable-колонки `distance_m:int`, `duration_s:int`,
  `crash_reason:str|None`, `max_mult:int`. `ScoreSubmit` — те же поля
  опционально, чтобы старый клиент не сломался.
- Анти-чит, мягко: `score <= duration_s * SCORE_PER_SEC_MAX`
  (`SCORE_PER_SEC_MAX = 400` в профиле настроек, тюнить по данным);
  нарушение → 422 `NCA_SCORE_IMPLAUSIBLE`. `score_max` пересмотреть
  после фазы 1: комбо поднимут потолок.
- Тесты: один заезд → ровно одна запись `ScoreRun`, `runs += 1`; старый
  формат тела принимается; неправдоподобный счёт → 422.

**Готово, когда:** за один заезд — ровно один POST; карточка показывает
дистанцию и место; снапшот обновлён (меняется HUD); pytest зелёный.

### Фаза 1. Комбо-цепь, жизни, мастерство (P2, P3, P4)

Модуль `game/combo.js` (владелец `state.combo`), подписан на события
модели. Счёт идёт только через него.

```ts
interface ComboState {
  pot: number; // несданные очки цепи (уже с множителем)
  n: number; // число действий в цепи
  mult: number; // текущий множитель
  timer: number; // секунд до закрытия цепи
  used: Partial<Record<TrickKind, number>>; // повторы трюков в цепи
}
// GameEventMap:
//   'combo':      { mult: number; pot: number; n: number }        // рост цепи
//   'combo-bank': { points: number; mult: number }                 // сдано в счёт
//   'combo-lost': { points: number }                               // сгорело при крэше
//   'life-lost':  { lives: number }
```

**Действия, которые продлевают цепь** (база очков → `pot += base * mult`,
`n += 1`, `timer = COMBO_WINDOW_S`):

| Действие                                             | База                     | Источник события             |
| ---------------------------------------------------- | ------------------------ | ---------------------------- |
| Взятое препятствие                                   | 50                       | `collide` → `'over'` + clear |
| Препятствие «впритык» (зазор над верхом < 0.08 cowH) | +25 и попап «ВПРИТЫК»    | то же                        |
| Приземлённый трюк                                    | `TRICKS[k].pts` × повтор | `land` после `airTricks`     |
| Двойной прыжок                                       | 30 (не +n)               | `trick` kind=double          |
| Вылет с рампы с чистым приземлением                  | 40                       | `airborne` launch + `land`   |
| Петля пройдена                                       | 150, `n += 2`            | `ride-exit` ok               |
| Трюк на петле                                        | +100                     | как сейчас `airBonus`        |
| Монета (фаза 3)                                      | 10, без `n`              | —                            |
| Полная линия монет                                   | 50, `n += 1`             | —                            |

- **Множитель.** `mult = min(COMBO_MULT_MAX, 1 + floor(n / 3))`,
  `COMBO_MULT_MAX = 8`. Повышение — попап `×N` и пульс бейджа.
- **Таймер цепи.** `COMBO_WINDOW_S = 3.0`, тикает **только** в
  `mode === 'ground'` на ровном. В воздухе, на рампе и в `ride` стоит:
  длинный полёт не рвёт цепь. Истёк → сдать горшок: `addScore(pot)`,
  событие `combo-bank`, попап «КОМБО +X», цепь в ноль.
- **Повторы трюков (PD4).** k-й повтор того же трюка в цепи даёт
  `pts × REPEAT_DECAY^(k-1)`, `REPEAT_DECAY = 0.5`. Разнообразие в
  одном вылете (≥2 разных вида) — ещё ×1.25 к базе вылета.
  Существующий «`mult` по числу трюков в воздухе» в `award` **удалить**:
  его заменяет цепь.
- **Идеальное приземление.** Трюк завершён не раньше чем за
  `PERFECT_WINDOW_S = 0.12` до касания → база вылета ×1.5, попап
  «ИДЕАЛЬНО». Если трюк докрутили «по дожиму» (сейчас `land` при
  прогрессе > 0.8 вызывает `finishTrick`) → «НЕЧИСТО»: очки есть,
  `n` не растёт. Нужен момент окончания трюка: `trickEndT`
  (`state.airT` в `finishTrick`).
- **Жизни (PD2).** `RUN_LIVES = 3`. Крэш:
  - горшок сгорает — попап «−X» красным, событие `combo-lost`;
  - `lives -= 1`, событие `life-lost`;
  - сданный `score` **не** обнуляется;
  - при `lives === 0` — `run-end`.

  HUD: 3 иконки-колокольчика у счёта (DOM, гаснут по одной). Текущее
  `score = 0` на `crash` в `score.js` — убрать.

- **HUD цепи.** Под счётом бейдж: `×4` крупно, рядом `+1 240` (горшок),
  под ним полоска таймера. Скрыт при `n === 0`. Цвет растёт с
  множителем (жёлтый → оранжевый → красный на ×6+). DOM + CSS,
  без canvas.
- **Туториал.** Два новых гейта в `tutorial.js`:
  - `combo` — когда впервые `n >= 3`: «Цепочка! Делай действия без
    пауз — множитель растёт. Упадёшь — несданное сгорит»;
  - `lives` — при первом `life-lost`: «Минус жизнь. Их три на заезд».
- **Демо/автопилот** очков не копит (как сейчас — `playerMode()`), но
  бейдж цепи в демо показывать: реклама механики.

**Баланс-проверка (обязательно до мержа):** headless-прогон автопилота
в player-режиме (через тест-хук снапшота) на 120 с. Сравнить средний
счёт «до/после» и записать в описание коммита. Ориентир: хороший заезд
в 2–4 раза дороже текущего. Под это поднять `score_max`.

**Готово, когда:** цепь растёт/сдаётся/сгорает; спам одного трюка
приносит заметно меньше, чем микс; 3 жизни; тесты счёта
(`npm run snapshot` + юнит на `combo.js`, если есть node-раннер —
иначе сценарий в снапшоте).

### Фаза 2. Кривая сложности: зоны и паттерны (P1)

**Зоны.** `zone = 1 + floor(distM / ZONE_M)`, `ZONE_M = 500`. Модуль
`game/difficulty.js` отдаёт чистую функцию
`params(zone) → {cruise, gapK, weights, patterns}`.

| Параметр                          | Зона 1 | +за зону | Предел |
| --------------------------------- | ------ | -------- | ------ |
| `cruise` (cowH/с)                 | 4.2    | +0.3     | 6.0    |
| `gapK` (множитель `gapAfterCowH`) | 1.0    | ×0.93    | 0.65   |
| `MAXSPD` с газом                  | 7.6    | +0.3     | 9.0    |

Доступ конструкций и паттернов по зонам:

- **Зона 1** — только одиночные низкие препятствия (cone, hay, tire,
  can) и кикер. Петля с зоны 2. Барьер и ряд конусов (`×2`) — с зоны 2.
- **Зона 2+** — петля, `×2`-препятствия, паттерны «двойка» и «рампа →
  препятствие на приземлении».
- **Зона 3+** — «лестница», «туннель газа», новые конструкции фазы 7
  по мере появления.

- **Граница зоны.**
  - Баннер «ЗОНА 2» по центру на 1.2 с (DOM) и +1 к `n` цепи
    («рубеж»); событие `zone` `{zone}`.
  - После баннера — 4 с чистой трассы: передышка, `clearSpawnX`.
  - Визуальная смена — тон неба/поля: CSS-фильтр `hue-rotate` на
    `#scene` или overlay-градиент с `mix-blend-mode`. Без переделки
    `sprites.js`. Палитры: день → закат → сумерки → ночь (циклом с 5-й).
- **Паттерны** — новые записи в `game/track/patterns.js`: таблица
  `{id, minZone, weight, items: [{type, dataOverride?, gapAfterCowH}]}`.
  `spawnFeatures` выбирает паттерн или одиночную конструкцию:
  `P_PATTERN = 0.25` с зоны 2. Каждый элемент проходит обычный
  `spec.plan` с перезаписью `data`/зазора. Движок по-прежнему не знает
  типов — паттерн это данные. Стартовый набор:

  | id        | Состав                                   | Чему учит                    |
  | --------- | ---------------------------------------- | ---------------------------- |
  | `pair`    | 2 низких препятствия, зазор 3.2–3.8 cowH | ритм: прыжок-прыжок          |
  | `ladder`  | 3 конуса с зазором 4.5 cowH              | цепь без пауз → комбо        |
  | `kickgap` | кикер → препятствие в зоне приземления   | трюк, который надо докрутить |
  | `gasrun`  | 3 препятствия, затем петля               | газ + прыжки одновременно    |

- `gapAfterCowH` сейчас считается внутри `plan` через `ctx.spdN`. Добавить
  `gapK` в `SpawnContext` и умножать в `spawnFeatures` (одна точка).
- `stepSpeed` берёт `cruise` из `params(zone)` вместо константы `CRUISE`.
  `state.boost`/`spdN` нормировать на `CRUISE` по-прежнему: визуал
  скорости не ломать.
- Защита от «нечестных» ситуаций: минимальный зазор между препятствиями
  на любой зоне не меньше времени `OLLIE`-полёта при текущей скорости
  - 0.25 с (проверка в `spawnFeatures` в секундах, не в cowH).

**Готово, когда:** через `?zone=3` (отладочный параметр, как `?feat=`)
сразу видна зона 3; снапшот покрывает зону 1 (поведение первых 500 м
меняется только паттернами — проверить); на телефоне FPS не просел на
зоне 5 (больше фич в кадре).

### Фаза 3. Клевер — четырёхлистники (P6, первая коллекция)

Конструкция `game/track/coins.js` по рецепту карты §5. Тип `coins`,
`collide` возвращает `'clear'` и помечает собранные. Коллектибл —
четырёхлистный клевер: корова на лугу и «удача» скейтера. Спрайт
рисуется кодом в `sprites.js`, как препятствия: 4 сердечка-листа
сочного зелёного, тёмная обводка, блик. Лёгкое вращение вокруг
вертикали — сжатие по X синусом, без 3D. Читается на тёмном асфальте.
При сборе — вспышка из зелёных искр (`sparks` с цветом).

```ts
interface CoinsData {
  shape: 'line' | 'arc' | 'loopTop';
  n: number;
  pts: [number, number][]; // [dxCowH от x0, hCowH] — позиции клеверов
  taken: boolean[];
}
```

Формы:

- **`line`** — 5 клеверов на высоте 0.15 cowH над асфальтом: собираются
  ездой.
- **`arc`** — 5 клеверов по параболе обычного прыжка: учит «прыгай здесь».
  С зоны 2 — по параболе двойного.
- **Над кикером** — дуга по траектории вылета. Ставит паттерн
  `kickgap`/кикер через `dataOverride`.
- **`loopTop`** — 1 золотой клевер (×5 очков) в верхней точке петли:
  берётся только при полном проходе.

Правила:

- Хитбокс: `|Xb − X| < 0.18 cowH` и `|h − hCoin| < 0.25 cowH`.
- Очки: клевер 10 × `mult` в горшок цепи. Полная линия → +50 и
  `n += 1`, попап «ПОВЕЗЛО!».
- Вес спавна низкий, не `special`. Можно ставить поверх ровного
  участка между фичами — нужна проверка «не пересекаться с
  препятствием по X».
- **Кошелёк.** `localStorage 'cow-skate-clover'` (`storage.js`: `readClover`/
  `writeClover`). Счёт заезда — в `RunStats.coins`, в HUD — маленький
  счётчик клевера с иконкой 🍀. Серверная синхронизация — фаза 5.
- Автопилот собирает линии (`autopilot` → `jump` у `arc`), демо
  показывает механику.

**Готово, когда:** `?feat=coins` спавнит линию первой; клевер
собирается и попадает в цепь; кошелёк переживает перезагрузку.

### Фаза 4. Соперник на экране (P5, PD6) — главный соц-крючок

**Источник соперников** — нативный топ чата через Bot API
`getGameHighScores(user_id, chat_id|inline_message_id, message_id)`:
Telegram отдаёт счёт игрока и **соседей по топу этого чата**. Плюс
глобальный топ из БД как запасной вариант (Mini App без игрового
сообщения).

**Бэкенд:**

- `GET /api/rivals?session=…` (и/или `init_data`). Ответ:

  ```json
  {"scope": "chat" | "global",
   "me": {"best": 1200, "position": 6},
   "above": [{"name": "@vasya", "score": 1430, "position": 5}, …до 5]}
  ```

  - `scope=chat`, если в claims есть контекст сообщения:
    `game_gateway.get_game_high_scores(...)` — добавить метод в шлюз,
    в тестах — фейк.
  - Иначе `scope=global`: до 5 игроков из `Player` с ближайшими
    `best_score` выше моего.

- Кэш ответа на 30 с в памяти на `(chat, message)`: при частых рестартах
  не долбить Bot API.
- Тесты: chat-скоуп через фейк-шлюз, global-скоуп, без идентичности → 401.

**Клиент** (`telegram-bridge.js` → игра — через DOM-события, как
`cowskate:run-end`, чтобы модули игры не знали про Telegram):

- На `run-start` мост тянет `/api/rivals` и шлёт `cowskate:rivals`
  `{above, scope}`. Игра (`ui.js`) держит отсортированный список целей.
- HUD-строка под счётом: `до @vasya — 230`. Прогресс-полоска до цели.
  Целевой счёт = **текущий счёт заезда + горшок цепи**: видно, что
  «сдай комбо — и обгонишь».
- Обгон (сданный счёт > цели) — попап «ОБОГНАЛ @vasya!», вспышка, +1 к
  `n` цепи. Следующая цель берётся из списка. Список кончился —
  «ТЫ #1 В ЧАТЕ!» (для `scope=chat`).
- **Твой рекорд** (без сервера): пока счёт < `best`, нижняя строка
  `до рекорда — 340`. Когда рекорд побит — попап «НОВЫЙ РЕКОРД!» один раз.
- **Флажок прошлого рекорда на трассе:** храним `bestDistM` в
  localStorage. Когда до него 30 м — на обочине появляется флажок
  «твой рекорд», рисуется как спрайт-фича без коллизии
  (`track/flag.js`, `special: false`, ставится `run.js` в `feats` на
  нужный X). Дёшево, но очень мотивирует «проехать дальше».
- **Карточка результата:**
  - кнопка «Похвастаться» → `proxy.shareScore()` (уже есть в оверлее
    топа — вынести в общий хелпер моста); показывать, если побит
    рекорд или кто-то обогнан;
  - строка «Обогнал: @vasya, @petya».
- Вне Telegram (standalone) соперников нет — работает только «до
  рекорда» и флажок.

**Готово, когда:** в группе с 2+ игроками HUD показывает реального
соседа сверху; обгон срабатывает; standalone без ошибок в консоли.

### Фаза 5. Цели между заездами: миссии, уровень, недельный топ (P6, PD7, PD8)

**Миссии** — `game/missions.js`, данные в `localStorage
'cow-skate-missions'`. Всегда 3 активные; выполнена — через карточку
результата заменяется новой из пула. Шаблон:

```ts
interface MissionTpl {
  id: string;
  text: string; // "Пройди {n} петли за заезд"
  tiers: number[]; // значения n по уровням сложности
  event: keyof GameEventMap; // на что подписана
  scope: 'run' | 'total'; // сбрасывается в конце заезда или копится
  check(detail, progress): number; // новый прогресс
}
```

Стартовый пул (≥ 15, тиры растут с уровнем фермера):

| Миссия                               | Тиры                  |
| ------------------------------------ | --------------------- |
| Набери N очков за заезд              | 1 000 / 3 000 / 8 000 |
| Проедь N м за заезд                  | 300 / 800 / 1 500     |
| Пройди N петель за заезд             | 1 / 2 / 4             |
| Сделай N сальто (всего)              | 10 / 30 / 80          |
| Собери N клеверов за заезд           | 15 / 40 / 80          |
| Достигни множителя ×N                | 3 / 5 / 8             |
| Сдай комбо дороже N                  | 500 / 1 500 / 4 000   |
| N идеальных приземлений за заезд     | 3 / 8 / 15            |
| Возьми N препятствий «впритык»       | 2 / 5 / 10            |
| Доберись до зоны N                   | 2 / 3 / 5             |
| Проедь первые 500 м без потери жизни | —                     |
| Трюк на петле N раз                  | 1 / 3 / 6             |
| 3 разных трюка в одном вылете        | 1 / 3 / 5             |
| Обгони N соперников (фаза 4)         | 1 / 3 / 5             |
| Заверши N заездов (всего)            | 3 / 10 / 25           |

- Прогресс — тихий попап «МИССИЯ 2/3» на изменении (не чаще 1 раза в
  2 с), выполнение — крупный попап + звёздочка в HUD.
- **Награда.** +клевер (100 / 250 / 600 по тиру) и +XP.
- **Показ.** Список 3 миссий — в демо-экране (`#cta`, под призывом) и
  в карточке результата (прогресс-бары).

**Уровень фермера.**

- XP = `floor(score / 100)` за заезд + награды миссий.
- Порог уровня `L`: `100 * L^1.5`.
- Уровень — значок у рекорда в HUD; влияет только на тиры миссий и
  открытие косметики.
- Хранение: localStorage; серверная копия — ниже.

**Косметика** (тратим клевер; только визуал, баланс не трогать):

- **Цвет доски.** Тинт спрайта `board` через offscreen-canvas с
  `globalCompositeOperation='source-atop'` → кэш в `sprites.js`.
  6 цветов.
- **След скорости.** Цвет `lines`/призраков: 4 варианта, огонь — за
  уровень 10.
- **Аксессуар на бирке.** Колокольчик/цветок — маленький спрайт,
  крепится к `tag` pivot.
- Магазин — простая DOM-карточка из демо-экрана (кнопка «🍀» рядом с 🏆).

**Серверная синхронизация прогресса** (чтобы не терять при смене
устройства):

- Таблица `PlayerProgress(user_id PK, clover, xp, level, cosmetics JSON,
missions JSON, updated_at)`.
- `GET/PUT /api/progress` с той же идентичностью (session/initData).
  Клиент — источник правды, last-write-wins по `updated_at`.
- Анти-чит не нужен: на топ не влияет.

**Недельный топ** (PD8, дёшево — данные уже в `ScoreRun` после фазы 0):

- `GET /api/leaderboard?period=week` — лучший `ScoreRun.score` каждого
  игрока с понедельника 00:00 МСК. Индекс по `created_at` уже есть.
- Вкладки в оверлее топа: «Неделя» (по умолчанию) | «Всё время».
- Бот в понедельник утром постит итоги недели в чаты, где за неделю
  играли ≥ 2 человек: топ-3 + «новая неделя — все с нуля».
  - Чаты — из `GameSession.chat_id`.
  - Планировщик — фоновая задача в lifespan с проверкой «уже отправлено
    на эту неделю» (новая таблица `WeeklyDigest(week, chat_id)`).
  - Требует отдельного согласования с пользователем перед включением
    (реальные сообщения в чаты) — по умолчанию выключено флагом
    `WEEKLY_DIGEST_ENABLED`.

### Фаза 6. «Трасса дня» (PD8) — честная гонка в чате

Все в этот день едут **одну и ту же трассу**: те же конструкции в тех
же местах. Споры в чате «как ты прошёл петлю после двойки?».

- **Отдельный генератор для спавна.** `utils.js: makeRng(seed)` (mulberry32).
  - `spawnFeatures` и `spec.plan(ctx)` берут случайность только из
    `ctx.rand`: сейчас `rand` из utils → заменить на генератор трассы.
    `pickSpec` тоже на нём.
  - Визуальные случайности (частицы, трещины, облака, автопилот)
    остаются на `Math.random`.
  - Это поведенческий коммит → новый эталон снапшота. Обычный режим
    сидит генератор от `Math.random()` один раз на старте заезда.
- **Режим.** `?mode=daily` в URL. Сид — `YYYYMMDD` по МСК, его отдаёт
  сервер в `GET /api/daily`: клиентским часам не верим.
  - Сброс трассы на каждый `run-start`: `feats`, `nextSpawnX`, `camX`
    к фиксированному старту.
  - 1 жизнь (без PD2) — классический формат «одна попытка за заезд,
    попыток сколько угодно».
- **Бот.** Команда `/daily` — отдельная игровая карточка или та же игра
  с флагом в session claims (`mode: 'daily'` → токен → URL). Предпочтительно
  claims: не нужен второй `game_short_name` в BotFather.
- **Топ дня.**
  - Таблица `DailyScore(date, user_id, best, attempts)`, PK `(date, user_id)`.
  - `POST /api/score` с `mode=daily` пишет и туда; сид проверяется по
    сессии.
  - `GET /api/daily/leaderboard?scope=chat|global`. Chat-скоуп — по
    `GameSession.chat_id` игроков дня.
  - Нативный `setGameScore` для daily **не** вызывать: перемешает
    обычный топ карточки.
- **UI.** Бейдж «ТРАССА ДНЯ · 2 окт» в HUD, в результате — место за
  день; соперники фазы 4 берутся из топа дня.

### Фаза 7. Новые конструкции (разнообразие трассы)

По `docs/gameplay-ux-plan.md` §C и рецепту карты §5. Каждая встраивается
в цепь фазы 1 и миссии фазы 5. Порядок:

1. **Высокий кикер** (`ramp` с `hr 0.5`): 2 трюка в вылете → разнообразие
   окупается.
2. **Стол** (tabletop): плато можно проехать (+1 `n`) или перепрыгнуть
   двойным с трюком.
3. **Рейл/грайнд** (`ride`): запрыгнуть с прыжка в окне по высоте. Очки
   за метр скольжения в горшок цепи, таймер цепи стоит. Баланс-метр —
   тап в ритм, иначе срыв `crash('fall')`. Самая «скейтовая» фича —
   высокий приоритет после стола.
4. **Пропасть** (gap): перелёт с разгоном, недолёт = `crash('fall')`.
   С жизнями (PD2) это уже не жёстко.
5. **Вупсы**: 3–4 холма, «пампинг» — тап на гребне даёт +скорость и `n`.

## 6. Как поймём, что стало лучше (метрики)

Считать SQL-запросами по `ScoreRun` (после фазы 0 там один ряд = один
заезд). Запросы положить в `backend/tools/metrics.sql`, снимать до и
после каждой фазы:

- заездов на игрока за сессию (цель: ×2 после фаз 1–2);
- средняя длительность заезда (`duration_s`);
- доля игроков, вернувшихся на следующий день (D1) и через 7 дней (D7);
- игроков на чат (растёт после фазы 4 — соц-крючок работает);
- распределение `crash_reason`: если `bail` > 50% — трюки слишком
  наказывают, тюнить окно.

## 7. Открытые вопросы (к пользователю, до фазы 1)

1. **Жизни (PD2):** 3 жизни на заезд или классика «одна ошибка — конец»?
   Рекомендация — 3: казуальной Telegram-аудитории так мягче, и только
   с ними работает «ставка» комбо.
2. **Бездействие:** автопилот перехватил → заезд кончается (рекомендация)
   или ставится на паузу до касания?
3. **Валюта:** четырёхлистный клевер 🍀 — ок как тема? (Запасные
   варианты: наклейки для доски — коллекционируются и сразу клеятся
   на деку как косметика; подшипники.)
4. **Еженедельный дайджест бота в чаты** — включать вообще? Это реальные
   сообщения в чужие группы.
5. **Трасса дня:** нужна ли до фазы 7 или после новых конструкций (с
   ними она интереснее)?
